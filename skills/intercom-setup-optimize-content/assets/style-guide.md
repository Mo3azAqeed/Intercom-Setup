# Default Style Guide

The optimize skill applies this style guide unless the user provides their own at `.intercom/style-guide.md`. A user style guide overrides any rule here that it covers.

## Voice

- Second person ("you"), active voice, present tense.
- Plain words over product jargon. If a product term is unavoidable, define it on first use.
- Short sentences. One idea per sentence.
- No marketing language ("powerful", "seamless", "effortless").

## Structure

Every article follows this order:

1. **Opening paragraph** — "Use this article to…" plus who it applies to (plans, roles).
2. **Sections** — one `<h2>` per task or question, phrased as the customer asks it.
3. **Limitations** — a section named for the limitation when there is one ("What happens when I reach my limit?").
4. **Related help** — links to related articles, if the original had them.

## Titles

- Phrase as the customer's question or task: "How do I…", "Why am I…", "What happens when…".
- Sentence case. No trailing punctuation except a question mark.
- Name the product feature in the title.

## Descriptions

- One sentence, ≤ 140 characters.
- Say what the reader gets, not what the article "covers".

## Formatting

- Numbered lists for steps, bullets for options.
- UI labels in bold exactly as they appear: **Settings → Billing**.
- Parameters, status codes, and commands in `<code>`.
- Every table and code block introduced by one sentence.
- "Important:" for anything that costs money, loses data, or can't be undone. "Note:" for helpful context.

## Numbers

- Numerals for all numbers ("5 USD", "2 credits", "48 hours").
- Units always stated.
- Currency: amount then code, as the source states it.
